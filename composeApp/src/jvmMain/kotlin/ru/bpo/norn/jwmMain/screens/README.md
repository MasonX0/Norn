# Структура компонентов экранов

## Общий принцип разбивки

Каждый экран в приложении разбит на отдельные компоненты для лучшей читаемости, переиспользования и
поддержки кода.

## Прогресс разбивки

### Завершенные экраны:

1. **Settings** - 4 компонента + основной экран
2. **Students** - 4 компонента + диалоги
3. **Enterprises** - 3 компонента + диалог редактирования
4. **Statements** - 2 компонента (простой экран)

### В процессе:

1. **TopNav Common** - 3 общих компонента созданы

### Планируется:

1. **InfoScreen** - самый сложный
2. **SummaryReport** - средний
3. **DestinationScreen** - средний
4. **OrderScreen** - сложный

## Принципы компонентов

### 1. Основной экран
- Содержит только логику компоновки и состояние
- Использует компоненты для отдельных секций
- Минимум UI логики

### 2. Компоненты секций
- Отвечают за отдельную функциональность
- Принимают необходимые параметры
- Содержат собственную логику отображения

### 3. Общие компоненты
- Располагаются в папке `common`
- Используются в нескольких экранах
- Обеспечивают единообразие интерфейса

## Статистика

### Создано компонентов:

- **Bottom Bar**: 15+ компонентов
- **Top Nav Common**: 3 компонента
- **Общих**: 3 компонента
- **Всего**: 21+ компонент

### Комментарии:

- Все компоненты имеют подробную документацию
- Сложные участки кода прокомментированы
- Все файловые операции документированы
- Интеграция с ViewModel объяснена

## Преимущества новой структуры

1. **Читаемость** - каждый компонент отвечает за одну задачу
2. **Переиспользование** - общие компоненты используются в разных экранах
3. **Тестируемость** - компоненты можно тестировать отдельно
4. **Поддержка** - легче находить и исправлять ошибки
5. **Расширяемость** - новые функции добавляются как новые компоненты
